What is Attendly?

Attendly is a student attendance management dashboard built as a 3rd-semester Computer Science Engineering college project. It helps students track their attendance across subjects, view their weekly timetable, monitor a monthly calendar, and calculate how many classes they can safely skip — or how many they must attend — to meet a target percentage.

The application demonstrates a complete client-server architecture using only core web technologies: no frameworks, no databases, no third-party UI libraries. Every part of the system — from the login flow to the bunk calculation — is implemented from scratch.

Key Features

Dashboard

SVG circular progress ring, summary stats, and subject cards — all driven by live API data.

Attendance Records

Subject table with Safe / Warning / Danger filters. Adapts to mobile card layout automatically.

Timetable

Day-tab weekly timetable with breaks and labs. Current weekday selected automatically.

Calendar

Full September 2026 calendar with colour-coded attendance and clickable day detail panel.

Bunk Calculator

Real-time formula solver. Calculates how many classes to skip or attend based on target.

Auth Guard

Session stored in localStorage. All protected pages redirect to login if no session found.

Authentication Flow

  1. Student enters roll number and password on the login page.
  2. Browser sends a POST /api/auth/login request with JSON body.
  3. Express route handler looks up the student in server/data/students.js.
  4. If credentials match, the server returns the student profile (no password).
  5. Browser stores the student object in localStorage and sets an auth flag.
  6. Every page calls requireAuth() — if no session exists, it redirects to login.
  7. Logout clears localStorage and redirects to the login page.

Data Storage Approach

This project intentionally avoids external databases (MongoDB, MySQL, etc.) to keep the setup simple and dependency-free. All sample data lives in plain JavaScript modules inside server/data/. The Express server imports these modules and serves the data as JSON through REST endpoints.

In a production system, these modules would be replaced by database queries. The REST API contract (endpoint URLs, request/response shapes) would remain the same — only the data layer would change.

Limitations (Demo Project)

  • Authentication is plain-text password comparison — not suitable for production.
  • No HTTPS — run locally only.
  • Data is hardcoded in JS modules — not persistent across server restarts.
  • No real JWT / session tokens — localStorage auth flag can be manually set.
  • Calendar data is only available for September 2026.
  • Only one demo student is provided in the data.
